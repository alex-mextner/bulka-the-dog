# Bulka: Astro + Conloca

The site keeps Bulka's existing design, photographs, contact destinations and
Russian, Serbian and English voice. Astro builds the pages as HTML. A single
React island hydrates each complete Puck page so the header, language switcher,
gallery registry and lightbox continue to share their contexts.

The public island renders the ten flat CMS block types directly through the
shared `BulkaSection` components inside `PageFrame`, using the same React tree
for static HTML and browser hydration. Puck and its field definitions remain in
the hosted editor's bundle. Both render paths share the components and authored
content; semantic parity tests cover all three languages and edited block data.

## Content and blocks

The live source of page content is `content/default/pages/*.vxjson`. The three
homepage files share the content ID `bulka-home`; their locale suffixes are
`ru`, `rs` and `en`. `content/sites.json` declares site `default` and those
locales. Serbian uses `rs` in content and URLs and `sr` in HTML `lang`.

Translations are grouped by their shared Conloca content ID, even when their
slugs differ. Each locale keeps its own pathname and alternate URL; for example,
Russian `/o-bulke` and English `/about` become `/o-bulke/` and `/en/about/`.
Unaddressed records are skipped rather than treated as a homepage.
Builds reject unsupported content locales, repeated versions of one document
that normalize to the same locale, and duplicate final output URLs. Recognized
RU, Serbian (`rs`/`sr`) and EN aliases keep their corresponding language routes;
the browser's separate language fallback does not admit other build locales.

| Puck block | Editable content |
| --- | --- |
| Hero | Heading, story, action labels, portrait, alternative text and caption |
| Appearance | Measurements, labels and photo |
| Habits | Heading and repeatable stories, symbols, photos and sticky-photo visibility |
| Skills | Story, photo and repeatable commands |
| Health | Story, photos and repeatable notes with icons |
| Conditions | Adoption conditions and photo |
| Questions | Heading and repeatable question/answer pairs |
| Contact | Contact text, exact destination URLs and map link |
| PhotoGallery | Heading and repeatable photos, thumbnails, alternative text and captions |

The nine core sections are accompanied by the optional `Game` block. It keeps
the original mini-game between Questions and Contact. It is present in authored
content so authors can move or remove it; the existing `VITE_ENABLE_GAME=1` flag
or its `PUBLIC_ENABLE_GAME=1` alias enables it on the public site. It stays off
by default and does not run in the hosted editor. The explicit public alias wins
when both variables are supplied. Both `1` and `true` enable a public flag.
An empty public flag is treated as unset: analytics retain their enabled
default, and the game falls back to `VITE_ENABLE_GAME`. Explicit `0` or `false`
still override those defaults.

Page fields hold navigation/footer copy and the social preview image. Standard
Conloca page settings supply the title and description used by the published
page. Blocks may be reordered, removed or repeated. New block IDs become unique
section anchors, and navigation follows the sections actually present.

For a new page, set **Page language** in the root fields to match its Conloca
document locale. The published site also reads the authoritative locale from
the content record. Conloca 0.2.1's Puck metadata locale describes data fetching
and does not reliably identify the language selected in the document editor.
New blocks therefore start with neutral copy and empty repeatable lists rather
than copying Russian migration text. Omitted copy uses the page's translated
fallback; an explicitly authored empty string remains empty. Existing authored
pages and the migration seed are not regenerated by this change.

Adding a repeated item may leave its text intentionally empty. Empty strings
are valid content; missing or non-string FAQ text and unsafe image URLs are rejected.
Incomplete FAQ items remain in saved data and the editor, but the public page
only renders a question when both its question and answer have text. An image
may explicitly use an empty alternative for a decorative placeholder. Editing
only an image URL can also leave its alternative absent: rendering then uses
`alt=""`, including gallery registration, without changing the saved object.
An explicitly supplied alternative must be a string.

Text fields named with `__` correspond to the existing translation keys:
`hero__title` means `hero.title`. The renderer treats text as text; the existing
small `**bold**` formatter produces React nodes and does not inject raw HTML.

Photo URL fields accept root-relative public paths or HTTP(S) URLs.
An empty or whitespace-only photo source means that the optional photo is absent.
Clearing it hides its image, gallery control and strip card, including any leftover
thumbnail; it does not restore a migration photo or rewrite the saved object.
Restoring a source restores the normal gallery and pinch behavior. Non-string
sources and nonempty unsafe URLs still fail publication validation.

Keep existing photos under `/images/`. Conloca-managed uploads use `/assets/`; the cloud editor's
draft-media adapter owns their preview URLs. The site renders relative paths
normally. Inside the hosted editor, existing public photos resolve against the
public origin of that exact build, without rewriting saved content.

Migration thumbnails remain paired with their original full-size photos. When
only a migrated photo's source URL changes, rendering ignores its leftover
migration thumbnail and displays the new source. Explicit custom thumbnails
remain author-controlled: update or clear that optional URL when replacing its
full-size photo. These display choices never rewrite saved photo objects.

`client/lib/translations.ts` supplies system UI strings and the initial migration
defaults. It does not overwrite author changes in `.vxjson` files. The original
homepage has 21 photos in the strip and 30 lightbox entries including section
photos; CMS authors may change those collections later.

The browser's language preference can update visible copy and descriptive
metadata without changing the URL. Canonical, `og:url` and JSON-LD page identity
continue to describe the requested Astro route.

## Development

Use Node 24 and pnpm 10.14.0. The lockfile pins the resolved dependencies.
Published Conloca packages are pinned to 0.2.1, with React 19 and Puck 0.23.0.

```sh
pnpm install --frozen-lockfile
pnpm dev
```

The dev server listens on `http://localhost:8080`. For a production-like local
check, run `pnpm build` and then `pnpm preview`.

`pnpm content:seed` creates only missing initial locale files. It is a migration
utility, not a build step. Its explicit `--force` option replaces those files;
do not use it on edited content.

Puck fields and defaults are committed as literal objects in
`src/puck.definitions.ts`, allowing Conloca to inspect every field without running
site code. If the block schema or initial defaults change, update
`scripts/generate-puck-definitions.mjs` / `client/cms/section-schema.json`, then run:

```sh
pnpm content:definitions
pnpm check
pnpm build
pnpm test:artifacts
```

This command regenerates developer-owned definitions, not authored pages. Keep
the named declarations in `src/puck.config.tsx`; a dynamically computed
`components` map can render at runtime while producing an incomplete component
manifest.

## Connecting a preview build to Conloca

Both integrations are configured in `astro.config.mjs`: React first, then
`conlocaCMS`, then `conlocaCloud`, using the same Puck config. A build token being
ready in Conloca is only the first step. Registration happens during a real
Astro build of the connected repository and branch.

| Variable | Purpose |
| --- | --- |
| `CONLOCA_BUILD_TOKEN` | Secret build credential supplied by Conloca; set in the build environment, never in content or source |
| `CONLOCA_ENDPOINT` | Organization origin; defaults to `https://alex-mextner.conloca.com` |
| `CONLOCA_PUBLIC_BASE_URL` | Exact publicly reachable origin serving this build and its `/_conloca/` assets |
| `CONLOCA_REQUIRE_REGISTRATION=1` | Fail the build if required registration cannot complete |
| `PUBLIC_SITE_URL` | Stable SEO origin; defaults to `https://bulka.rs`, independently of the preview asset origin |
| `PUBLIC_ENABLE_ANALYTICS` | Existing analytics remain enabled by default; `0` or `false` disables all three providers together |

On Vercel, the public base URL defaults to `https://${VERCEL_URL}`. Outside Vercel,
set `CONLOCA_PUBLIC_BASE_URL` explicitly for a registered build. Local development
defaults to `http://localhost:8080`. A normal preview build without a token still
produces the site and editor assets and logs that registration was skipped; it
does not claim the site is connected.

Canonical links, locale alternates, social URLs and structured data use the
stable SEO origin. Conloca editor images and bundles use the exact build's public
origin. A Vercel deployment URL must not replace the production canonical URL.

Use the exact pushed commit of the connected branch. Configure the token in that
preview build's environment and run the ordinary Astro build. Deploy the same
output at the declared public origin, then confirm Conloca reports the build as
registered and can open its editor. If testing in a disposable organization,
override the endpoint and public base URL and use that organization's token.

The editor bundle is native ESM built by Conloca's esbuild pipeline, outside
Vite's `import.meta.env` transform. Astro config calls
`scripts/public-environment.mjs` to create the ignored module
`src/generated/public-environment.ts` from an explicit public allowlist. Site
components import those ordinary constants, so both bundlers use the same public
origin. No process environment is spread into the bundle, and no tracked source
or authored content is rewritten. Tokens never become client constants. Editor
analytics and experimental game/donation panels are disabled by runtime ownership.
The analytics flag is read once for Umami, Vercel Analytics and Speed Insights;
`1` and `true` have the same meaning. Its default does not depend on Vercel-only
environment variables, allowing the same registered build to reproduce its
editor bundle on another build host.

Vitest initializes that module only when it is absent in a fresh checkout. It
preserves the bytes from an existing build even when the test process has no
matching environment variables. The metadata artifact check reads the saved
`siteUrl` and analytics flag, including a configured `PUBLIC_SITE_URL` override.
Astro still refreshes the module for each new build with changed settings.

## Deployment contract

Vercel keeps the previous long-lived cache policy for `/images/`, known static
root images and hashed `/_astro/` files. CMS-managed `/assets/` is excluded from
`immutable`: Conloca can reuse a deleted upload's filename for different bytes.
The editor's CORS headers remain enabled on all four resource prefixes.

`vercel.json` uses the Astro preset and serves `dist`. It includes CORS headers for
`/_conloca/`, `/images/`, `/assets/` and `/_astro/`. Do not add a catch-all rewrite to
`index.html`: missing URLs must return 404, and editor bundles must remain actual
JavaScript/CSS/JSON assets.

The browser must be able to fetch the declared `/_conloca/` URLs anonymously from
the Conloca origin. A deployment sign-in page is not an editor bundle even if its
HTTP status is 200. Verify public access, JavaScript content type, CORS and the
registered hashes against the deployed bytes.

Create and verify a branch preview before considering production. Changing
production aliases or merging into the production branch is a separate action.

## Verification

```sh
pnpm check
pnpm test:content
pnpm test
pnpm build
pnpm test:artifacts
```

`test:content` checks locale behavior, safe URLs, unique section anchors, portable
editor assets, initial language parity, contacts and repeatable data.
`test:artifacts` inspects the generated component manifest for all nine blocks,
their nested fields and defaults, and rejects unresolved vocabulary or a native
editor bundle that still depends on `import.meta.env`.

Against an already running built preview:

```sh
E2E_BASE_URL=http://localhost:8080 timeout 300 pnpm exec playwright test tests/e2e/astro-cms-migration.spec.ts --reporter=line
```

The migration suite covers 360/390/768/1440 px, horizontal overflow, loaded photos,
RU/SR/EN content and document metadata, navigation, FAQ, lightbox next/previous,
Escape, focus restoration, original contact links, real 404 and HTML without
JavaScript. The deployment CORS assertion runs against a public deployment, where
Vercel applies headers; Astro's local preview does not apply `vercel.json`.

Retain the existing gallery/gesture suites for pinch-to-open, zoom, photo-strip
scroll and the mobile viewport. Emulated Chromium does not prove real Safari
behavior; verify Safari on a real device when changing those interactions.

Finally, test the real hosted Conloca editor: import the registered bundle, load
photos, edit a text field and repeated item, save and reload, then publish and
confirm the resulting git content and rebuilt public page. The editor must not
change its parent document title, language, theme or URL when rendering Bulka
blocks. `SiteRuntimeContext` enables browser ownership only on the published
site; canvas navigation/lightbox controls remain inert while content stays
editable through Puck.
